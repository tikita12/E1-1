## 레벨 0 — 준비운동: 지금 뭐가 있는지 둘러보기 👀

**🎯 목표:** Docker에게 "지금 가진 게 뭐야?"라고 물어보는 3가지 질문을 익힌다.

**🧠 왜?** 요리 시작 전에 냉장고(이미지)·조리 중인 냄비(컨테이너)·창고(볼륨)를 확인하는 것과 같아요.

**⌨️ 직접 쳐보기:**
```powershell
docker images
docker ps -a
docker volume ls
```

**👀 성공 모습:** 표가 3개 나옵니다. (`mission-web:1.0`, `nginx:alpine` 등이 보일 수 있어요)

**✅ 체크:**
- [ ] `docker images` = 가진 **틀(이미지)** 목록이 나왔다
- [ ] `docker ps -a` = 만든 **붕어빵(컨테이너)** 목록이 나왔다 (꺼진 것 포함)
- [ ] `docker volume ls` = **사물함(볼륨)** 목록이 나왔다

**🤔 스스로 설명:** `docker ps`와 `docker ps -a`의 차이는?
> 👉 정답: `docker ps`는 **켜져 있는(Up)** 것만, `-a`는 **꺼진(Exited) 것까지 전부** 보여줍니다.

## 레벨 1 — 터미널과 경로 감각 잡기 🧭

**🎯 목표:** "나 지금 어디 있지?"와 절대/상대 경로를 체감한다.

**🧠 왜?** 터미널은 항상 "현재 위치"가 있어요. 상대 경로는 그 위치 기준, 절대 경로는 전체 주소예요.

**⌨️ 직접 쳐보기:**
```powershell
Get-Location
Get-ChildItem -Name
Get-ChildItem site
```

**👀 성공 모습:** 현재 위치가 `...\mission-web\practice`로 나오고, 폴더 안에 `Dockerfile`, `site`, `compose.yaml`이 보입니다.

**✅ 체크:**
- [ ] 현재 위치가 `practice` 폴더다
- [ ] `site`라고만 쳤더니 그 안의 `index.html`이 보였다 (= **상대 경로**, 현재 위치 기준)

**🤔 스스로 설명:** `site`와 `C:\Users\bshin\mission-web\practice\site`의 차이는?
> 👉 정답: 앞은 **상대 경로**(현재 위치에서 옆방), 뒤는 **절대 경로**(전체 주소). 바인드 마운트에선 절대 경로를 써야 합니다.

## 레벨 2 — (선택·Ubuntu) 파일 권한 바꾸기 🔐

> ⚠️ 이 레벨만 **Ubuntu(WSL) 터미널**에서 합니다. 윈도우만 쓸 거면 건너뛰어도 돼요.

**🎯 목표:** `chmod 600`으로 "나만 보는 일기장" 파일을 만든다.

**⌨️ 직접 쳐보기 (Ubuntu):**
```bash
mkdir -p ~/practice-perm
touch ~/practice-perm/diary.txt
ls -l ~/practice-perm/diary.txt
chmod 600 ~/practice-perm/diary.txt
ls -l ~/practice-perm/diary.txt
```

**👀 성공 모습:** 권한 표시가 `-rw-r--r--` → `-rw-------`로 바뀝니다.

**✅ 체크:**
- [ ] 바꾼 뒤 맨 앞이 `-rw-------`가 됐다 (주인만 읽기·쓰기)

**🤔 스스로 설명:** `600`이 왜 "주인만 읽기·쓰기"인가요?
> 👉 정답: 읽기4+쓰기2=6(주인), 그룹0, 나머지0 → `600`. 주인에게만 4+2=6을 준 것.

## 레벨 3 — Docker 첫 인사 & 상태 읽기 👋

**🎯 목표:** `hello-world`로 Docker가 살아있는지 확인하고, Exited 상태를 이해한다.

**⌨️ 직접 쳐보기:**
```powershell
docker run hello-world
docker ps -a
```

**👀 성공 모습:** `Hello from Docker!` 메시지가 뜨고, `docker ps -a`에 hello-world가 **Exited (0)**로 보입니다.

**✅ 체크:**
- [ ] `Hello from Docker!`를 봤다
- [ ] hello-world가 **Exited**다 (인사만 하고 할 일 끝 → 퇴근)

**🤔 스스로 설명:** 왜 hello-world는 Exited인데 웹서버는 Up일까요?
> 👉 정답: hello-world는 메시지 출력이 끝나면 할 일이 없어 종료. 웹서버는 손님을 **계속 기다려야** 해서 켜진 채 유지(Up).

## 레벨 4 — 컨테이너는 "작은 별도 컴퓨터" 🚪

**🎯 목표:** 컨테이너 안에 직접 들어가 명령을 실행하고, `exit` 해도 안 꺼지는 걸 확인한다.

**🧠 왜?** 컨테이너는 내 PC 안의 작은 컴퓨터. exec는 "그 방에 손님으로 들어가기"예요.

**⌨️ 직접 쳐보기:**
```powershell
docker run -d --name practice-ubuntu ubuntu sleep infinity
docker exec -it practice-ubuntu bash
```
이제 **컨테이너 안**입니다 (`root@...:/#`). 안에서:
```bash
ls
echo "hello from inside"
exit
```
다시 내 PC로 나온 뒤:
```powershell
docker ps
```

**👀 성공 모습:** `exit` 했는데도 `docker ps`에 `practice-ubuntu`가 **Up**으로 남아 있습니다.

**✅ 체크:**
- [ ] 컨테이너 안에서 `ls`, `echo`가 실행됐다
- [ ] `exit` 후에도 컨테이너는 **Up**이다 (나간 것 ≠ 끈 것)

**🤔 스스로 설명:** `sleep infinity`를 왜 붙였나요?
> 👉 정답: ubuntu는 할 일이 없으면 바로 꺼져요. "계속 자고 있어라"로 **안 꺼지게** 유지해야 exec로 들어갈 수 있습니다.

## 레벨 5 — 나만의 이미지 만들기 (Dockerfile → build) 🍕

**🎯 목표:** 레시피(Dockerfile)로 **틀(이미지)**을 굽는다.

**🧠 왜?** `Dockerfile(레시피) ─build→ 이미지(틀) ─run→ 컨테이너(붕어빵)`

**⌨️ 먼저 레시피를 눈으로 확인:**
```powershell
Get-Content Dockerfile
```
→ 2줄이 보입니다: `FROM nginx:alpine` (가벼운 웹서버 바탕), `COPY site/ ...` (내 페이지 넣기)

**⌨️ 틀 굽기 (build):**
```powershell
docker build -t practice-web:1.0 .
docker images
```

**👀 성공 모습:** 빌드가 `FINISHED` 되고, `docker images`에 `practice-web:1.0`이 생깁니다.

**✅ 체크:**
- [ ] `practice-web:1.0` 이미지가 생겼다
- [ ] 빌드 로그에서 `FROM`과 `COPY` 두 단계가 지나갔다

**🤔 스스로 설명:** 맨 끝의 `.`은 뭘까요? 그리고 다시 build 하면 `CACHED`가 뜨는 이유는?
> 👉 정답: `.`은 **"지금 폴더"**(빌드 재료가 있는 곳). `CACHED`는 **이미 받아둔 nginx 도우를 다시 안 받고 재사용**한다는 뜻.

**⌨️ (보너스 관찰) 한 번 더 build 해서 CACHED 확인:**
```powershell
docker build -t practice-web:1.0 .
```

## 레벨 6 — 실행하고 포트로 접속하기 🚪➡️🏠

**🎯 목표:** 틀로 붕어빵(컨테이너)을 찍고, 브라우저로 접속한다.

**🧠 왜?** `-p 9080:80` = "내 PC 9080 현관으로 온 손님을 컨테이너 80호로 안내".

**⌨️ 직접 쳐보기:**
```powershell
docker run -d --name practice-web -p 9080:80 practice-web:1.0
docker ps
curl.exe -i http://localhost:9080
```
그리고 **브라우저 주소창**에 입력: `http://localhost:9080`

**👀 성공 모습:** `HTTP/1.1 200 OK`와 `practice: hello docker!`가 보입니다. 브라우저에도 같은 글자가 떠요.

**✅ 체크:**
- [ ] curl 결과가 **200 OK**다
- [ ] 브라우저에 `practice: hello docker!`가 보인다

**🤔 스스로 설명:** `-p 9080:80`에서 왼쪽/오른쪽은 각각 뭐죠?
> 👉 정답: **왼쪽(9080) = 내 PC**, **오른쪽(80) = 컨테이너**. 접속은 왼쪽 번호로 합니다.

## 레벨 7 — 바인드 마운트 = "유리창" 🪟 (핵심!)

**🎯 목표:** 내 PC 폴더를 컨테이너에 "유리창"으로 연결하고, **재빌드 없이** 수정이 바로 반영되는 걸 체험한다.

**🧠 왜?** 레벨 6 방식(COPY)은 파일을 **복사해 넣은** 거라, 고치면 매번 재빌드해야 해요. 바인드 마운트는 **같은 폴더를 공유**(유리창)해서 즉시 반영됩니다.

**⌨️ ① 유리창으로 연결해 실행:**
```powershell
docker run -d --name practice-bind -p 9081:80 --mount "type=bind,source=C:\Users\bshin\mission-web\practice\site,target=/usr/share/nginx/html,readonly" nginx:alpine
curl.exe -i http://localhost:9081
```
→ `practice: hello docker!`가 보입니다.

**⌨️ ② 이제 PC에서 파일을 고쳐보세요.** `practice\site\index.html`을 열어 글자를 바꾸세요. 예: `practice: I changed it!`
> 메모장으로 열어도 되고, 아래 명령으로 한 번에 바꿔도 됩니다:
```powershell
Set-Content -Encoding utf8 site\index.html "<h1>practice: I changed it!</h1>"
```

**⌨️ ③ 재빌드 없이 다시 접속:**
```powershell
curl.exe -i http://localhost:9081
```

**👀 성공 모습:** **빌드를 다시 안 했는데도** 9081 응답이 `I changed it!`으로 바뀝니다!

**✅ 체크:**
- [ ] 파일만 고쳤는데 9081 페이지가 바로 바뀌었다
- [ ] (비교) 9080(`practice-web`)은 아직 **옛날 글자** 그대로다 → `curl.exe -i http://localhost:9080`

**🤔 스스로 설명:** 왜 9081은 바뀌고 9080은 안 바뀔까요?
> 👉 정답: 9080은 **이미지에 복사(COPY)**된 내용이라 재빌드해야 바뀜. 9081은 **유리창(바인드 마운트)**이라 PC 파일과 실시간 공유 → 즉시 반영. (이미지와 컨테이너는 분리돼 있다!)

## 레벨 8 — 볼륨 = "사물함" 🗄️ (데이터 영속성)

**🎯 목표:** 컨테이너를 **지워도** 데이터가 살아남는 걸 두 눈으로 확인한다.

**🧠 왜?** 컨테이너를 지우면 안의 데이터도 사라져요. 중요한 건 Docker가 관리하는 **사물함(볼륨)**에 넣습니다.

**⌨️ ① 사물함 만들고, 글 저장:**
```powershell
docker volume create practice-data
docker run -d --name practice-vol1 -v practice-data:/data ubuntu sleep infinity
docker exec practice-vol1 sh -c "echo saved-in-volume > /data/hello.txt"
docker exec practice-vol1 cat /data/hello.txt
```
→ `saved-in-volume`이 출력됩니다.

**⌨️ ② 컨테이너를 완전히 삭제!**
```powershell
docker rm -f practice-vol1
```

**⌨️ ③ 새 컨테이너에 같은 사물함 연결 → 꺼내보기:**
```powershell
docker run -d --name practice-vol2 -v practice-data:/data ubuntu sleep infinity
docker exec practice-vol2 cat /data/hello.txt
```

**👀 성공 모습:** 글 쓴 컨테이너를 **지웠는데도** 새 컨테이너에서 `saved-in-volume`이 그대로 나옵니다!

**✅ 체크:**
- [ ] `practice-vol1`을 삭제했다
- [ ] 그런데도 `practice-vol2`에서 `saved-in-volume`이 나왔다 (= 데이터 영속성)

**🤔 스스로 설명:** `/data`는 어디에 있는 폴더이고, 실제 글은 어디 저장됐나요?
> 👉 정답: `/data`는 **컨테이너 안**의 폴더(사물함으로 통하는 문). 실제 글은 **`practice-data` 볼륨(사물함)**에 저장돼서, 컨테이너를 지워도 남습니다.

## 레벨 9 — (보너스) Docker Compose = "주문서 한 장" 📝

**🎯 목표:** 긴 명령 대신 `compose.yaml`로 한 줄 실행을 체험한다.

**⌨️ 레시피(주문서) 확인:**
```powershell
Get-Content compose.yaml
```
→ `build: .` (이 폴더로 빌드), `ports: 9082:80` 가 보입니다.

**⌨️ 한 줄로 실행:**
```powershell
docker compose up -d
docker compose ps
curl.exe -i http://localhost:9082
```

**👀 성공 모습:** 이미지 빌드 + 컨테이너 시작이 자동으로 되고, 9082에서 200 OK.

**✅ 체크:**
- [ ] `docker compose up -d` 한 줄로 빌드+실행이 됐다
- [ ] 9082로 접속됐다

**🤔 스스로 설명:** Compose를 쓰면 뭐가 편한가요?
> 👉 정답: 긴 `docker run` 명령을 매번 안 치고 **파일에 적어두고 한 줄로 실행·정리**. 여러 컨테이너도 한 번에 관리.

**⌨️ Compose 정리:**
```powershell
docker compose down
```
